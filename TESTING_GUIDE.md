# FoundRisk Edge — Local Test Guide

## Start
1. Extract the ZIP.
2. Open the folder containing `run.py` and `requirements.txt` in VS Code.
3. In PowerShell run:
   ```powershell
   py -m venv .venv
   .\.venv\Scripts\Activate.ps1
   python -m pip install -r requirements.txt
   python run.py
   ```
4. Open http://127.0.0.1:5000.

## Test Feature 1 and Phase 2
1. Create/select a project.
2. Upload `testing/FoundRisk_Test_Due_Diligence.pdf` and click **Process**.
3. Analysis should show six observations: Revenue ₹4.5 Cr / ₹8.2 Cr; Customer Count 180 / 340; Market Size ₹1,200 Cr / ₹1,500 Cr, associated with FY2025 and FY2026.
4. Evidence should show each extracted observation with source page and supporting text.
5. The contradiction area should show the actual observations. With only this one document, cross-document finding count correctly remains zero.
6. To test a discrepancy, upload a second supported document containing the same metric, same period, and same currency but a different value. The engine should show both sources, the difference, and a review severity.

## Important
- Different reporting periods are not contradictions.
- Different currencies are not auto-converted.
- A discrepancy is a review flag, not proof of fraud or falsity.
- Scanned/image-only PDF OCR uses local Tesseract when installed; verify `tesseract --version` and install the needed language data before testing scanned PDFs.

## Evidence Explorer checks
1. Open **Evidence** after processing a real supported document.
2. Confirm each record shows its source filename and only the page/sheet/cell/row fields actually captured.
3. Click a record and verify the drawer shows original source text, extraction signals, original and normalized values, and provenance status.
4. Search by a phrase from the excerpt, a source filename, or a spreadsheet location; matching evidence should appear.
5. Try each metric, confidence, and document filter; use **Reset** to clear all filters.
6. Export visible records to CSV and verify the export includes source filename and location.
7. For records without captured provenance, confirm the UI says the source location is unavailable rather than showing a guessed location.

## Reliability regression checks

1. After sign-in, leave the workspace open and test creating a project, processing a document, changing a finding status, renaming a project, and importing/saving a report. API writes should carry the current CSRF token; an old tab should refresh the token once and retry.
2. Open Risk Findings after processing the included sample PDF. The queue should show evidence-coverage review prompts for metric families that only appear in one source. The counts should load even when a category has zero findings.
3. Ask Copilot about revenue, customer count, market size, and a reporting period. It should return extracted source statements with citations, or a clear no-match message—never invented figures.
4. For scanned PDF OCR, install Tesseract on the same machine as the Flask server, upload a scanned PDF, and process it. Check that the document is ready, the page provenance is retained, and the response includes `ocr_pages`.
5. Benchmarks accepts the JSON report produced by `tools/qaihub_npu/run_npu_smoke_test.py`. A PDF such as the startup diligence sample belongs in Documents, not the report importer. A real hosted Qualcomm AI Hub run and its profile evidence are still required before claiming NPU utilization.

## Existing workspace data

When replacing project files, stop the app first. Keep your existing `instance/foundrisk.db` and `uploads/` folder so your account, projects, and source files remain available. Back them up before applying a new build.


## Important: choose the correct JSON importer

- **Financial due-diligence test data** (with fields such as `documents`, `claims`, or `expected_test_cases`) must be uploaded through **Documents** and then processed for extraction, evidence, contradictions, and risk findings. Do not upload it in Runtime Benchmarks.
- **Runtime Benchmarks** accepts only the real report generated by `tools/qaihub_npu/run_npu_smoke_test.py`, normally `instance/qaihub_npu_report.json`. The report must include `product`, `test_scope`, `device_requested`, `overall_status`, `checks`, and `job_ids`.
- A manually written/sample JSON cannot establish that Snapdragon NPU execution happened. Only import a report from an actual completed Qualcomm AI Hub run.
